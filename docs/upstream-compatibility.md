## 官方 1.0.0 → 1.0.2 的实际变更

官方范围共包含 8 个提交、14 个文件、198 行新增/70 行删除。唯一的运行时行为修复是两份
截图 toolcode：base64 PNG 的大小上限从 `(1_048_576 * 3) // 4` 调整为
`((1_048_576 - 2048) * 3) // 4`，为外层 JSON 包络预留 2 KiB，从而避免边界大小截图被
MCP 1 MiB 消息限制拒绝。

其余变更如下：

| 类别 | 官方改动 | 对本项目的影响 |
| --- | --- | --- |
| 依赖 | MCP SDK 限制为 `>=1.2.0,<2` | 已在本项目 1.0.0 实现，且有相同原因。 |
| 工具可发现性 | 为 `search_api_docs`、`search_manual_docs` 补 docstring | 小幅提高官方 tools 的 schema 描述质量，不改变搜索能力。 |
| 安装文档 | 修正 Git pip 安装的 `#subdirectory=mcp` | 对本项目推荐的 `uv --project mcp` 工作流无运行时影响。 |
| README 生成 | 将官方工具清单移至 `readme_tools.rst` | 文档维护改进，不改变 Server。 |
| manifest/版本 | 官方包从 1.0.0 标记到 1.0.2 | 仅官方发布元数据。 |
| lint/Makefile | Ruff 与生成脚本配置 | 开发体验改进；不改变 Add-on、TCP wire protocol 或 MCP 工具语义。 |

官方 `addon/pyproject.toml` 的改动也只是 lint 配置；Add-on 代码和 Bridge 协议在该范围内
没有改动。

## 迁移成本

以共同祖先 `v1.0.0` 对本项目 `super-v1.0.0` 与官方 `v1.0.2` 进行三方合并预演：

- 截图修复、工具 docstring、requirements、文档生成文件和开发配置可自动合入。
- 只有两个文本冲突：`mcp/pyproject.toml`（本项目自身的包名、版本、`pydantic` 依赖）和
  根 `readme.md`（本项目入口说明）。
- `mcp/manifest.json` 必须保留本项目自己的发布版本，不能直接使用官方 `1.0.2` 版本号。
- 需要重跑 official profile 快照、agent layer 测试及真实 Blender 隔离端口测试。

因此完整同步属于**低成本、但并非无缝**的迁移；没有协议升级或 Add-on 迁移成本。

## 结论

官方 `v1.0.2` 并非本项目“当之无愧更好”的替代品：它可靠地解决了一个截图边界故障，
但没有解决本项目的核心痛点——Agent 为常见任务生成自由 `bpy` 代码、全场景回包偏大、
没有 session identity/revision 重试语义、工具面不分层，以及缺少默认安全回退策略。

本项目保持 `super-v1.0.0`，不整体迁回官方并误称为 `1.0.1`。未来发布可以选择性回移
截图 2 KiB 余量与搜索工具 docstring；这种“回移”应以本项目自己的补丁版本发布，并在
变更记录中明确说明，而不是假装成官方基线迁移。
